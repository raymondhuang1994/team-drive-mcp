# 0.6.1：网络资料根外祖先的最小读取权限

此前 Windows 网络来源会对路径上的每一级目录申请 `GENERIC_READ`。某些团队共享盘只允许员工读取资料根，而上级组织目录仅允许读取属性；Windows 能访问资料，程序却在核验上级目录时被拒绝。

0.6.1 为这种权限组合修正运行时的打开方式：只对批准的网络资料根之外的严格祖先目录申请 `FILE_READ_ATTRIBUTES (0x80)`。资料根、根内目录和文件仍要求正常读取权限。该规则按规范化路径组件判断，不硬编码盘符、公司服务器或文件夹名称，也不修改共享盘权限。

## 修改范围

- 源码位置为 `python/team_drive/fs_access.py`；完整 Skill 包中的对应位置为 `runtime/python/team_drive/fs_access.py`。更新说明文字不能替代运行时更新。
- `_handle` 使用独立的属性读取模式；既有 `metadata_read` 控制私有元数据文件的共享方式，不作为本次权限选择开关。
- `_WindowsDirectories` 以固定资料根区分严格祖先、资料根及内部目录，记录打开模式，使首次核验和 `check()` 重新打开一致。
- `WindowsSource` 首次核验、`_parent_guard` 和 `check_root` 始终传递同一个批准根，不能把正在访问的子目录当成新的根。

SMB 协议、文件身份、DFS 实际目标、重解析点、来源边界及句柄共享检查继续生效。祖先属性无法读取、根或文件没有正常读取权限、来源身份发生变化时仍拒绝；不会自动改用更低权限接受目标资料，也不会跳过失败的校验。本地来源、固定本地索引和 Microsoft Graph 的权限规则不因此改变。

## 升级与验收

发布使用完整 ZIP，根目录唯一 `SKILL.md`，其旁保留 scripts/、runtime/、references/ 和完整性清单。安装前核对发布记录中的 ZIP SHA-256，按当前客户端的升级流程备份完整旧安装并停止相关旧连接；不要在正在运行的安装目录中单独覆盖一个 Python 文件。索引和配置保持在独立本地目录，不随安装包覆盖或移入共享盘。

SkillHub 的展示版本与包内运行时是不同字段；例如 Hub 仍显示 `0.2.0`，不能证明当前读取程序已经升级。应核对完整包清单、正式安装目录中的运行时 `0.6.1`，并在新进程连接后确认 `status.service_version`。

Windows 现场验收按包内的 [网络盘升级验收步骤](../skills/df-mcp/references/windows-share-acceptance.md) 执行：

1. 正式安装的新进程执行 `plan`，展示实际资料根与固定本地索引位置。
2. 获得对应配置确认后 `apply`，再启动索引并检查任务终态、覆盖和读取缺口。
3. 在已确认来源中选择至少一个真实文件，用返回的 `file_id` 完成 `inspect`，再携带其 `source_version` 执行 `read`，返回内容、版本和定位。

`plan` 成功、配置保存和索引就绪是不同阶段。单文件读取成功也不证明整个资料库完整可读。若开发会话不在公司 Windows 电脑上，自动测试只能验证合成权限场景和程序行为；实际共享盘、DFS、当前用户权限与真实文件的验收应另行记录，不能由模拟或 CI 结果替代。
