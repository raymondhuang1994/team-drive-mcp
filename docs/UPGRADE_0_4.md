# 升级到 0.4

0.4 保持 **本机 stdio MCP＋共享 broker＋SQLite** 架构，强化证据定位、检索与评测。此版本没有新增共享盘连接器、镜像同步、HTTP MCP、多用户权限或 OCR；OCR 仅完成[可行性调查](OCR_FEASIBILITY.md)。

## 本轮变化与职责

| 内容 | 实际变化与边界 |
| --- | --- |
| 默认检索 | 保留关键词、中文短词、别名与文件级匹配；排序采用精确路径/短语优先、BM25、稳定路径次序 |
| 上下文 | 新增 `team_drive_context`，以指定版本读取命中片段和有界候选上下文，保留 locator、选择原因和未包含范围 |
| 问题分流 | 新增 `team_drive_plan`，用确定性规则建议查找、版本比较、全量工作或澄清；建议不是最终判断 |
| 可选模型 | 配置本地 embedding 后支持 semantic；hybrid 以 RRF 合并 BM25 和语义候选；rerank 单独启用并由调用选择 |
| 运行记录 | 新增 `team_drive_diagnostics`，只保存有界的操作名称、耗时、结果与错误代码，不记录查询、正文或路径 |
| 评测 | `npm run evaluate` 生成合成语料并检查检索、证据、分页、更新/删除和汇总，输出机器可读报告 |
| Skill | 更新取证决策与新工具用法，仍需实际连接对应 MCP 服务才能执行 |

MCP 服务负责实际文件读取、来源边界、版本验证与结构化结果；Skill 指导 Agent 怎样使用这些结果。提示词无法补出服务没有提供的证据，工具测试通过也不等于 Agent 的最终回答正确。

## 兼容性

- 原 stdio 启动参数 `--config`、`--python`，连接名与 `team_drive_` 工具前缀保留。
- 原 10 个工具继续提供，新增 context、plan、diagnostics 后共 13 个。search 新参数默认 `mode="keyword"`、`rerank=false`；旧调用仍可执行，相关性排序可能改善或变化。
- 未添加 `retrieval` 的旧配置保持模型关闭；旧资料根目录不会自动更换。操作诊断默认开启，可显式关闭。
- 工具与 broker 仍检查源文件版本及会话游标。跨会话、旧版本或过期的 cursor 需要重新取得；更新 Skill 不会复活已经断开的 stdio 会话。
- 代码与索引签名变化会使旧提取缓存失效，首次连接可能重新索引。索引重建完成前检查 `current_job_id`、job_status 和 coverage，不能据旧的完成状态宣布当前全库可用。
- 磁盘数据库不是承诺长期向前/向后兼容的交换格式；导出、证据包、实际配置和原始资料需独立保留。

## 建议升级顺序

1. 在旧连接中保存 status 的服务版本与来源身份，记录实际 Node、Python、源码和 JSON 配置位置。保留旧安装及配置副本。
2. 关闭使用该配置的客户端，等待旧 broker 退出。停止后备份状态目录，包含既有 JSONL 导出和证据包；不要复制正在写入的 SQLite 工作文件当作一致备份。
3. 在经过核对的 0.4 源码目录安装依赖并构建。保留来源选择，使用现有配置；以下命令不重新选择资料目录：

```sh
npm ci --ignore-scripts
npm run setup -- --skip-config
npm run install:skill -- --replace
```

`install:skill --replace` 会校验新副本并备份旧 Skill。Skill 与服务源码应一起更新，但它们仍是两个独立安装位置。

4. 用新目录、Node 和专用 Python 的实际路径更新原 MCP 注册条目，保留已确认的 `--config`。不要新增一个重复连接，也不要同时用两个版本操作同一状态目录。
5. 完整退出并重新打开客户端，调用 status 和工具列表。应看到服务版本 0.4.0、13 个工具、原来源身份、共享模式；默认 semantic/rerank 关闭，`network_calls=false`。
6. 等待索引完成，使用获准样本验证 search → inspect → context/read → 引用。版本、定位、提取缺口和原文件内容都应能核对。两条本机会话可检查是否共用同一实例。

可先运行合成评测，报告保存在明确指定的位置：

```sh
npm run evaluate -- --output .local/evaluation-keyword.json
```

这不会连接现有资料配置，也不生成 LLM 答案。使用真实资料验收前仍需定义问题、人工标准答案、正式来源和不应作答的情形。模型接口的模拟测试只验证协议和降级逻辑，不能证明真实模型带来准确率提升。

## 回退

关闭新版连接并等待 broker 退出，再恢复保留的旧运行目录、旧 JSON 配置和旧 Skill。需要恢复状态时使用升级前停止状态下的备份；不要让旧版直接读取新版数据库来试探兼容性。没有一致状态备份时，应按旧版受支持的配置流程为同一获准来源建立明确的独立状态，再重新索引。

回退不删除源资料，也不要丢弃新版生成的证据包和导出。核对这些产物后单独保留。重新连接后用实际 status 验证服务版本和来源；仅修改源码文件或 Skill 不能证明运行服务已经回退。

## 可选模型不是默认升级步骤

本轮不自动安装或下载模型，也不把真实资料发送给外部服务。需要语义或重排时，按[模型配置说明](RETRIEVAL_CONFIGURATION.md)单独配置获准的本地服务。填写并维护模型 revision，检查索引覆盖、降级、候选上限和耗时，然后用同一资料与同一题集比较关键词基线；准确性不退步后再考虑用于实际问题。
