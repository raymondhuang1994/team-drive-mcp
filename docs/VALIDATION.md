### 0.1 程序测试覆盖

- 来源边界：目录越界、符号链接、源目录祖先被替换、扫描中目录重绑定、普通文件被替换成 FIFO；失败会明确返回，不读取外部来源或阻塞整个服务。
- 索引一致性：新增、修改、删除、未变化失败重试策略、配置变化失效、直接使用 Python 引擎时的解析子进程启动。
- 证据一致性：文件大小和修改时间均未变而内容改变、过期版本拒绝、绑定版本/查询/筛选条件的分页游标、受控完整导出。
- 结构与数据：中文短词和别名、CSV 逻辑行与带换行字段、长单元格、XLSX 工作表/坐标/隐藏/合并/公式缓存、空表与仅含图形表的覆盖警告、DOCX 段落与表格、PPTX 文本/表格/备注、文字 PDF。
- 错误与限制：超限不静默截断、不支持格式保留在清单、XML DTD/实体与 ZIP 展开限制、缺少文本的 PDF、解析失败不沿用旧成功正文、输出上限、单状态目录单 worker。

MCP 集成使用 6 个模拟文件，实际验证工具发现、清单/正文分页、中文与别名检索、结构检查、CSV 指定行、精确整数分计算、JSONL 导出、长文末尾、越界拒绝以及修改后版本更新。测试未将工具数量本身当作业务正确性的证据。

独立边界复核曾发现并推动修复源目录祖先重绑定、FIFO 替换可能阻塞的问题；修复后单独重验，并加入回归测试。此记录不是第三方安全认证，也不覆盖所有操作系统和恶意文件变体。

### 0.1 性能基准

环境：macOS、Python 3.9.6；使用 0.1 当时的最终引擎代码，生成 1,000 份短文本及一张含 50,000 条数据记录的 CSV，共 1,001 个文件。首次索引全部成功。复现命令：

```sh
.venv/bin/python scripts/benchmark.py --files 1000 --rows 50000
```

| 指标 | 实测 |
|---|---:|
| 冷启动完整索引 | 38,298.26 ms |
| 热关键词查询中位数，30 次 | 2.41 ms |
| 热关键词查询近似 P95，30 次 | 2.65 ms |
| 读取 CSV 末行，含源文件 SHA256 检查 | 11.04 ms |
| 全文件结构化 JSONL 导出 | 330.96 ms |
| 一份文件修改后的完整目录核对及增量处理 | 2,355.75 ms |

这里的查询计时仅覆盖本地后端，不含模型推理、MCP 客户端往返、联网或人工复核。短文本和 CSV 不能代表大体积 Office/PDF 文件；未测峰值内存、十万文件目录、云端占位文件和真实网络挂载。这是单次环境记录，不是服务延迟保证。

关键取舍：证据读取会重新计算源文件 hash，大文件存在顺序 I/O 成本；首轮解析与大目录轮询也有成本。需要真实代表性文件后，才能进一步决定分层索引、原生文件监听、并行解析或向量检索是否值得引入。

### 0.1 时点的边界

- 0.1 支持 macOS/Linux，原生 Windows 拒绝启动；此历史限制在 0.2 加入 Windows 后端后改变，当前范围以文档顶部为准。
- SharePoint/Teams 在线授权和下载、多用户身份与权限过滤尚未实现。
- 不包含 OCR、视觉理解、公式重算或业务来源自动认证。格式限制必须随答案保留。
- 一个状态目录只允许一个活跃服务进程；源目录改绑或版本变化会拒绝继续沿用旧证据。
- 轮询只在进程运行时持续；取消发生在安全文件边界，中断文件需重新解析。
- 测试数据不能代替真实团队的来源登记、指标口径、模板和业务验收。

公开版本只包含通用代码、规范和虚构样本。运行配置、索引、缓存、导出、工具完整轨迹、依赖安装目录及个人路径均不应进入 Git；检查器不能替代发布者对内容的人工审查。
