# Windows 本地目录与只读部署

本说明适用于 df mcp 的 Windows 本地后端。普通安装只配置读取范围与私有状态位置，不改变源资料的权限，不安装系统服务，也不授予程序管理员权限。程序和 Skill 的测试结果见 [验证记录](VALIDATION.md)。

## 支持的目录

选择固定本地磁盘上的普通文件夹，例如 `D:\团队资料`。中文和空格可以保留，无需重命名。程序目录必须在源目录之外，源与状态目录不能互相包含。状态使用默认 `%LOCALAPPDATA%\df-mcp` 或明确的其他外部目录；任何 `.codex` 祖先目录与自定义 `CODEX_HOME` 均不可作为状态存储位置，包含物理别名检查。临时修复的迁移步骤见 [Windows 迁移说明](WINDOWS_MIGRATION.md)。

本版拒绝 UNC/网络映射盘、可移动盘、设备路径、符号链接、junction 和其他 reparse 路径；源文件具有多个硬链接时也拒绝读取。Windows cloud reparse 文件可能在已下载后仍保留云属性，因此不能将“文件在资源管理器里可见”或“已下载”当作已经支持。在线占位文件不强制下载；先将获准测试资料复制到普通、非同步本地目录。

这些排除可能导致索引覆盖不完整。查看 `team_drive_status` 和文件清单中的失败/排除项，不能把未读文件算作空白内容。

## 程序如何保持源只读

Windows 后端以 `GENERIC_READ` 和 `OPEN_EXISTING` 打开已存在的源文件，不申请写入或删除权限；同时核验文件句柄对应的最终位置和身份。源目录链通过打开的目录句柄固定，拒绝重定向路径。相应接口语义见 Microsoft 的 [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) 与 [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。

- 安装和配置不向源目录写探测文件，不更改源 ACL。
- MCP 不提供源修改、删除、移动、重命名或改权限接口。
- 解析读取独立快照；临时文件、SQLite、日志和 JSONL 导出写到独立状态目录。
- 生成导出的路径由服务控制，调用者不能传入任意输出位置。
- 多个 MCP 连接通过本机 named pipe 共享一个受管理 Python 引擎和索引；只有 broker 持有数据库租约，不让多个进程直接写同一 SQLite。客户端断开不删除索引，broker 空闲后退出。
- 安装更新、Skill 迁移与缓存清理仅针对程序自己的文件，不能递归清理源目录。

源目录句柄不共享删除权限，运行期间可能阻止其他程序重命名或移除该目录；关闭服务后再整理目录。此安全边界仍保留。状态目录必须位于 Codex 配置目录之外，避免状态路径句柄把 `.codex` 固定后影响 Codex 的原子替换。源文件可以同时被其他程序编辑，程序通过内容 hash 及身份检查发现变化并拒绝混合版本；遇到共享锁定或权限不足时报告失败，不解锁文件、不改 ACL。

“源只读”指本服务不改源内容、名称、结构或权限。操作系统可能按文件系统规则维护访问时间，其他已获写权限的程序也仍然可以修改资料。程序不会尝试撤销这些系统行为。

## 需要操作系统强制只读时

普通桌面配置通常让 MCP 与 AI 客户端使用当前登录账户。源只读代码和工具契约约束本 MCP，**不能撤销该账户、宿主终端或其他文件工具已有的写权限**。需要把整个运行身份限制为只读时，由 IT 提供独立受限账户或合适的隔离环境。

建议由 IT 在复制的合成测试目录先验证以下部署，再按公司流程配置真实资料：

| 资源 | 运行身份所需权限 | 检查重点 |
|---|---|---|
| 源目录及文件 | 列目录、读取内容/属性、按需遍历 | 无写入、追加、新增、删除、改权限或改所有者权限 |
| 源目录父层级 | 到达源目录所需的最小读取/遍历 | 不能通过父目录的 Delete child 权限删除或替换受保护条目 |
| 程序及依赖目录 | 读取/运行 | 由维护身份更新；运行身份不能替换程序或解析器 |
| 配置目录 | 读取 | 由维护身份管理已批准的根目录，避免运行身份自行改读其他位置 |
| 独立状态目录 | 创建、读取、修改和删除自身派生状态 | 不与源或程序目录重叠；其他普通身份不能读取敏感缓存 |

检查账户的所有组成员身份、继承项、有效访问权限及所有者能力。单独加一条“读取”授权并不会移除其他组已有的写入或删除授权；源文件本身的权限也不能替代父目录删除子项权限检查。ACL 的读取、写入、删除、修改权限和所有者权限是不同能力，见 [Windows 文件访问控制](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。

本项目不提供给当前用户批量添加 deny 的一键脚本，也不在安装时重置 ACL。错误的 deny 或继承修改可能影响本人和同事正常工作。IT 可使用 Windows“高级安全设置”的有效访问页面检查身份；`icacls` 支持查看和保存 ACL，修改选项应由管理员按其变更流程选择，见 [icacls 官方说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)。

仅把一个目录的“只读”属性打勾不能代替上述访问控制配置。独立账户的启动、凭据管理和 stdio 客户端衔接需要由 IT 另行配置，本版安装器不自动创建账户或提权。

## 验收步骤

1. 用可丢弃的模拟资料创建测试源、独立程序目录和独立状态目录，保留初始文件清单、内容 hash、修改时间及 ACL 记录。
2. 由 IT 以预定运行身份确认读取可用；仅对可丢弃的测试资料尝试新增、修改、删除、重命名和改权限，预期均被操作系统拒绝。不要在真实资料上用破坏性操作测试权限。
3. 启动 MCP，运行索引、搜索、检查、读取、分页、导出、刷新和取消；核对读取证据正确、写入仅落在独立状态目录。
4. 关闭服务后比对源清单、内容 hash、修改时间和 ACL，检查没有程序造成的变化。
5. 测试中文/空格路径、文件占用、越界、junction/reparse、目录身份改变和状态路径重定向。失败应明确返回，不能读到授权范围外或写回源目录。
6. 在公司实际客户端中确认 AI 其他终端和文件工具的权限符合目标。如果宿主仍在更高权限身份下运行，本 MCP 的受限身份不能替整个宿主提供隔离。
7. 按[并发与重启验收](WINDOWS_MIGRATION.md#目标-windows-电脑验收)在实际 Codex 同时开启至少两条聊天，分别检查状态并读取同一已有文件，确认无 `STATE_IN_USE` / `EBUSY`；退出并重开 Codex 后再次读取，并检查同一服务/索引复用及离线清理。独立 SDK 客户端测试不能替代这一步。

测试成功只覆盖测过的身份、文件系统、路径类型和版本，不代表任意恶意程序或所有公司 Windows 策略已经验证。团队正式使用还需要各用户自己的授权、缓存保护和维护责任。
