# 0.6.2：网络扫描进度与正式复测

在资料根预检通过后，较慢的共享盘扫描可能在发布完整清单前触发预算。旧版只报告 SHARE_TIMEOUT 和零个已索引文件，无法判断清单收集到了哪一步。0.6.2 保留完整清单发布要求，增加独立进度与阶段耗时，并减少同一次网络元数据观察中重复的根链核验。

## 运行时变化

- `job_status.job.scan_progress` 区分枚举目录、枚举条目、已核验条目和待发布文件；它们不等于正式文件总数。记录固定操作的次数、累计/最大耗时、进行中次数与当前等待时长。嵌套耗时存在重叠，不能直接求和；预算也不会硬取消正在进行的原生 Windows I/O。
- `job_status.job.error_detail` 保存受控阶段、错误说明、可取得的原生错误码及有限项目代码帧，不保存原始异常文本、完整路径、查询、正文或局部变量。未捕获到的错误信息保持 null，不编造 Win32 码。
- `status.index_status` 将服务可响应与索引是否就绪分开。首次网络清单尚未发布时，list/search 返回 INDEX_NOT_READY；之前已发布的候选仍需当前权限与版本核验，并明确覆盖缺口。
- 网络 observe 使用一次完整且新鲜的父目录保护，其本身覆盖批准根及祖先；不跨文件缓存权限，不改变普通本地来源或内容读取检查。合成目录链每项句柄打开从 8 次降至 5 次，仅表示该测试场景的调用量变化，不是生产提速承诺。
- Windows 默认状态基目录通过系统 Known Folder 信息和原生目录检查确定，贯穿计划、创建及配置保存。plan 不创建目录；不硬编码应用包名或改写任意自定义路径。无法证明现有默认目录与目标一致时拒绝另建 profile，避免悄悄产生第二份索引。

扫描预算仍默认 120 秒，已有配置范围最高 600 秒。根据阶段耗时和实际进展决定是否调整；此版本不自动放宽预算、不更换来源、不修改共享权限。解析器和 OCR 范围不变。

## 安装与复测

升级完整 ZIP/.skill，不能仅替换 SKILL.md；保留已有独立配置与索引。根目录直接包含唯一 SKILL.md，运行时版本 0.6.2。按照包内 [Windows 验收说明](../skills/df-mcp/references/windows-share-acceptance.md) 核对正式安装，再复用已经确认的配置执行 `scripts/df-check.py`。

复测入口不安装程序、不执行 apply、不强制刷新，也不修改来源。首次连接可以启动已配置的扫描，因此要求 `--confirmed-config`。报告只输出脱敏 JSON；真实文件内容在当前公司环境内核对，不进入回传摘要。报告中的自动版本/定位结构检查不等于业务内容准确性审阅。

下一次现场应确认：同一配置、本地索引和来源；扫描任务及覆盖；至少一个真实文件的 inspect/read 和同一版本；有实际索引时的重复检索耗时。若仍超时，回传同一任务的计数、最后阶段与耗时，避免反复索要完整原始日志。

## 验证边界

回归覆盖慢速与超时、清单不部分发布、旧清单不误删、运行中进度可读、失败记录复用、网络访问拒绝、原生临时 SMB、首次默认状态映射及报告隐私。具体结果以对应提交 CI 和交付测试记录为准。模拟的 Windows 默认目录映射与 CI 不能代替公司应用打包环境；真实 DFS、MSIX 首次安装和业务文件读取仍须现场验证。
